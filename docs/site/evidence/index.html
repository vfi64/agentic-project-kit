History and architecture

Historical observations · 2026-10-16

What did the gates actually catch?

Known work-order faults were probed, mitigations were added, and an offline comparison checked selected gate behaviour. These are bounded observations, not a current security certification.

Read the evidence at its own scope

A public manifest acknowledgement is not author authentication. A green gate checks named rules; it does not prove correct requirements, general prompt-injection resistance or universal protection of every execution path.

The findings and results below predate the current package. No new benchmark, remote mutation or model run was performed to generate this page.

Mitigations recorded in that review

WOTB-01, WOTB-02, WOTB-03, WOTB-05, WOTB-06

Typed command_argv and transfer run_command run READ_ONLY Kit commands and read-only git/gh queries. BOUNDED Kit commands, BOUNDED cockpit actions and commands outside the manifest need the local --allow-unlisted flag on transfer continue, transfer remote-next, transfer apply, transfer run-local, remote-next/rn, work-order typed-next and work-order typed-run. DESTRUCTIVE Kit commands, raw git/gh mutations and interpreters are refused even with the flag. The refusal happens before any action of the order runs.

WOTB-07, WOTB-08

The anchor must be a full 40-character hash. It must equal HEAD for an uncommitted order, and otherwise the first parent of the commit that last changed the order file. transfer remote-next checks status, kind, branch and anchor again after switch and pull, on every path including an explicit or inferred branch (transfer continue). The order that runs is therefore the order that was checked. transfer order-validate uses the same binding.

WOTB-04, WOTB-09

work-order run --execute, the next-turn.py fixed slot (next_turn_runner, GUI work-order run) and current.sh (agent_command_runner) no longer execute anything. They report BLOCKED_RETIRED_LANE, keep their evidence and point to typed work orders, transfer orders and the planner executor. The validators stay as format checks. The commands are removed after the deprecation window.

Some unrestricted execution lanes were retired rather than made into sandboxes. Format validation must not be mistaken for command authorization. See the dated review for the individual probes and limitations.

What this does not establish

  • These are known scenarios that informed the fixes. This is not an independent held-out security evaluation.
  • The differing denominators are not general security percentages, and the result does not measure unknown fault detection.
  • The offline experiment exercised neither live GitHub/CI/release services nor real adversarial repository access.
  • One deterministic run per scenario does not establish performance across machines, cost savings or absence of false positives in other repositories.
  • The separate paid context pilot had invalid fault injection and contaminated reference history. It provides no confirmatory effectiveness or token-saving result; further runs remain deferred.
