Minimal cycle

Task To Handoff

  • Select the interaction modeChoose File Transfer, Copy and Paste, Agent Direct, or the experimental GUI surface.
  • Inspect before mutationUse read-only or dry-run commands where available and keep target-owned decisions explicit.
  • Run a bounded sliceMake one coherent change on a branch, record gates and evidence, and keep PR review visible.
  • Close the handoffGenerate the successor package so another session or executor can continue from repository state.

Why not only Git, CI and AGENTS.md?

The Kit complements Git and CI; it does not replace them. Git records history, GitHub coordinates PRs, CI validates configured checks, and AGENTS.md guides an executor. The Kit keeps long-lived operational state, governance, evidence, command metadata and handoffs in the repository.

Boundaries

What Persists

  • Git records history and diffs; the Kit adds machine-readable operational state and handoff contracts.
  • GitHub PRs coordinate review; the Kit wraps PR lifecycle checks when evidence is available.
  • CI validates configured checks; the Kit records when remote target-CI is absent or not claimed.
  • AGENTS.md guides an executor; the Kit keeps durable governance, evidence and command metadata in the repository.
  • The executor is replaceable; repository governance persists.
  • The Kit itself makes no LLM API calls and does not require an LLM API; executor services may have their own costs.
  • YAML and JSON state are versioned, diffable and reviewable, but they create file volume and projection-refresh work.

State format

Why YAML And JSON

Repository state is versioned, diffable, reviewable, and portable between sessions, machines and executors. The tradeoff is more files and explicit projection refresh work instead of an invisible state service.
