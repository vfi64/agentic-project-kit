# W1, W3 and W4: generated navigation, detail and history

The combined slice follows D1 and reuses its shared schema-3 task authority.
It changes the generated website, not command permissions or runtime behavior.
No release, consumer retest or paid benchmark is part of this work.

## Projection boundaries

- W1: eleven reviewed intents grouped by their existing phase, progressive search,
  explicit state predicates and inputs, unassigned-command disclosure and full
  catalog links. Selection never authorizes execution.
- W3: twelve detail pages from the exact union of reviewed task routes and the
  already tested quickstart. Descriptions, options, safety and conditions derive
  from the same validated manifest, including secondary boolean options such as
  execute/no-merge. Added examples only run local help; existing
  quickstart fixtures cover the onboarding sequence. No inferred call relations.
- W4: a public field allowlist from the cleared self-hosting archive, pinned by
  source manifest and member digests, plus the current normative architecture.
  Archive-reported events, testimony and bounded measurements are identified.
  Private-source inventories and raw consumer details are not exported. Existing
  reviewed figures are reused; no universal lock, kernel isolation or productivity
  benefit is claimed. Current main architecture links are explicitly moving.

The site shows source-tree metadata; this is not a promise that unreleased
commands exist in an installed published package. Historical sources remain
unchanged. Typed projections feed deterministic HTML, avoiding a second manual
task taxonomy or history document. This uses the existing projection design
rather than introducing a new DCO framework.

79 passed, 8 warnings. They exercise twelve inert help examples, shared-manifest
mutation, source tampering, public-field privacy and local links/anchors.

details and history: no document-level horizontal overflow; eleven cards restored
after clearing search, zero-match live feedback and keyboard disclosure verified.

cover language, unique IDs and labelled inputs.

selection/detail rendering and bounded history extraction live in focused

outside this bounded slice.

## Remaining boundaries

Browser accessibility acceptance is bounded keyboard/label/focus testing, not
a complete WCAG certification. Unassigned command semantics and broader primitive
detail pages remain deliberately unclaimed. No new trace or benchmark was run.
