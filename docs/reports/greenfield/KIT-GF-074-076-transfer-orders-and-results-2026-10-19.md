# KIT-GF-074, KIT-GF-075, KIT-GF-076: transfer command orders and published order results

Date: 2026-10-19
Kit state: CLOSED in candidate; planned fix release 1.1.2. Consumer VERIFIED_FIXED remains independent.

## Observation

A consumer ran a live file-transfer order with Kit 1.1.1: the order was generated by
`transfer order-create`, validated and executed by `transfer remote-next <branch> --json` from a
clean `main` checkout with result PASS, and the remote-next reports were pushed to the transfer
branch.

- KIT-GF-074: `order-create` could only generate `write_text_file` actions, although the runner
  executes `run_command` actions; command orders had to be written by hand.
- KIT-GF-075: after PASS the checkout stayed on the transfer branch with three untracked files:
  the written target, the order's command-run report and `LATEST_COMMAND_RUN.txt`. The
  transferred file never reached the branch, and the next Kit route met a dirty checkout.
- KIT-GF-076 (found by this slice's regression fixture): `workspace init` writes
  `.agentic/transfer/inbox/.gitkeep`, and the transfer state counted it as an obsolete transfer
  file, so remote-next in a freshly initialized workspace stopped with
  `run_next_command is false`.

## Repair

- `order-create --run-command '<argv>'` (repeatable) parses one shell-quoted argv, passes it
  through the runner's action parser and the order command authority, records
  `command_authority` with `requires_allow_unlisted`, and refuses commands that no local flag can
  allow. The runner starts an order's `agentic-kit` commands with the workspace's own Kit
  (`default_agentic_kit`, else the running interpreter) and reports 127 when a command cannot be
  started, instead of a missing transfer order.
- `remote-next` collects the order products (written targets that exist and are not ignored, the
  confined command-run report, the LATEST pointer) and adds them to its first report commit.
  Every other changed or untracked path after the order (`git status -uall -z`) is recorded as
  `unexpected_worktree_changes`, never staged, and makes the result BLOCKED.
- The transfer state accepts `.gitkeep` in inbox and outbox.

## Regression

`tests/test_transfer_order_products_and_commands.py` runs the installed wheel in an external
workspace with a bare origin: a write order ends PASS with a clean checkout and the target,
report and pointer on the origin branch; command orders are written with the needed authority;
six refused commands write no order; a READ_ONLY command order ends PASS and clean; an
undeclared stray file blocks and is not published; `.gitkeep` carriers no longer conflict while
another inbox file still does; an unstartable command reports 127.

## External retest

```text
agentic-kit transfer order-create --branch {branch} --write-action {target}={payload} --execute --json
agentic-kit transfer remote-next {branch} --json
```
