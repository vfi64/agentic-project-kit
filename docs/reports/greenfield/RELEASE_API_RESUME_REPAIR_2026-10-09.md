# Release API failure and DOI PR resume repair

Status: completed local validation; governed PR closeout follows
Review policy: evidence report; immutable after slice closeout

## Finding

Release 1.0.22 D4 stopped after green CI for existing DOI PR #2456, head
`8fc3074b6cb7a33773e518a9b6d382d807cd2bd4`, because GitHub GraphQL exhausted
its quota. `wait_for_pr_readiness` treated all API errors as terminal; D4's
legacy failure flag selected replacement recovery for every failure. A failed
source lookup then incorrectly reported ambiguity. Source: recorded local
release-run D4 evidence, not a newly assigned Cockpit finding number.
Cockpit ledger source last read: `c31eb2dc3dcea2cd9f8b86ae6a9fdc60adad2577`;
the Cockpit ledger is unchanged.

## Repair

- Named transient read failures receive at most two retries within the existing
  wait deadline. Read failures and retry delays remain observable in readiness
  output and orchestrator logs. Quota/authentication errors and red CI stop.
- Legacy D4 evidence with a failed `pr-wait-ci` and `GH_ERROR` selects the
  `resume-existing` mode of D2R. Its fresh signature binds version, tag, original
  PR, source branch/head, base, state and current main. Recheck before action.
- Open originals compose exact-head `transfer pr-complete` with post-merge
  completion. Merged originals require recorded merge evidence on current main
  and compose `transfer post-merge-complete`; a merge alone never means PASS.
- Resume identity is persisted before effects, so an interrupted handoff resumes
  against the original PR. No replacement, retagging or package publication.
- Genuine regeneration failures retain replacement recovery. Lookup unavailable,
  missing and ambiguous results have separate blockers. Failure logs are kept.

## Risks and boundaries

Legacy evidence without an identifiable original PR and head keeps the existing
replacement route. No heuristic invents a missing head or quota reset. GitHub
read calls retain their existing subprocess timeout behavior; retries never
extend the intentional polling deadline. The new core is separate from CLI
adapters and the existing replacement workflow. DCO adds no benefit here:
existing typed gate/state artifacts already provide deterministic signatures and
selective step resumption. Published 1.0.22 artifacts remain immutable; this repair
requires a later release to reach installed consumers.
